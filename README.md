# Recros

Recros is a cross-domain recommendation app for discovering movies, books, and music through one evolving taste profile.

## Milestone 2 (October 2026)

The [three-domain follow-up](docs/milestone2/hierarchy/domains/RESULT.md) now adds
320 held-out book profiles and 181 held-out song listeners, with real Goodreads
ratings and recording-level Last.fm plays joined to AcousticBrainz genre labels.
At 50% simulated missing labels, mean annotation-bit lookup reductions are 6.5%
for movies, 2.4% for books and 1.3% for songs. No domain establishes a ranking
gain; validation retains the reference ranking. These are independent
within-domain tests, not evidence of linked-user cross-domain transfer.

The [held-out follow-up](docs/milestone2/hierarchy/heldout/RESULT.md) joins 1,242
ontology-labelled films to 3.84 million MovieLens ratings and evaluates 320
historical test profiles after validation on 128 separate profiles. It measures
6.5% fewer mean missing-label lookups for the same recommendations at 50%
masking, with positive paired bootstrap savings. It **does not establish a
ranking-accuracy gain**; the severe-missingness test exposes a ranking failure,
and validation selects the historical baseline. The
[ten-slide evidence deck](docs/milestone2/deliverables/Recros_strengthened_result.pptx)
includes the benefit, failure, compute tradeoff and scope. This movie-only test
uses simulated missing metadata, not a new human or book/song preference study.

The latest [hierarchy result](docs/milestone2/hierarchy/RESULT.md) derives an exact
graph formulation for shared preference uncertainty and incomplete hierarchical
tags, plus a conservative structural-fault bound. The [live research demonstration](http://127.0.0.1:8008/hierarchy)
shows impossible flat-label worlds and the fault allowance. Its 276 masked
film/book states are a controlled structural experiment, not a human preference
study. [Proof and scope](docs/milestone2/hierarchy/DERIVATION.md), [attribution](docs/milestone2/hierarchy/NOVELTY_CHECK.md)
and [eight-slide result deck](docs/milestone2/deliverables/Recros_hierarchy_result.pptx)
are saved. Global originality remains unverified.

Open [the evidence lab](http://127.0.0.1:8008/lab). The lab uses cached annotations
generated by **DeepSeek V4 Flash** through the existing **Command Code** subscription. It needs no model
download or live inference. Its 12 sourced real works form a curated software demo,
and 15 fictional records remain available as test fixtures.
The separate MovieLens pilot uses real ratings and measures the discovery tradeoff.

The [decision lab](http://127.0.0.1:8008/decision) now chooses between asking,
inspecting cached evidence, recommending and abstaining. Its
[24-task controlled comparison](docs/milestone2/results/policy/RESULTS.md) finds a
tie between the exact planner, information gain and DeepSeek; this is a mechanism
test with scripted preferences, not a human-accuracy result.

Use [familiar-work selection](http://127.0.0.1:8008/familiar) to search the recovered
222,896-item catalog instead of forcing a participant to rate unfamiliar demonstration
works. The [representation audit](docs/milestone2/REPRESENTATION_AUDIT.md) checks whether
oppositely rated works have become indistinguishable in the supplied features.
Personal preferences and clarification records remain in the ignored local data directory.

The [automatic discovery app](http://127.0.0.1:8008/explore) now searches
222,915 works and immediately gives five movies, five books and five songs,
including the starting domain. Optional refinement comes afterward: free text,
37 feature shortcuts, sourced genres with include/exclude and AND/OR, plus
language, origin, setting mentions and period mentions. The report's seven
weights are preserved, with missing signals omitted and normalized. Recent and
less-popular slots support discovery; known/disliked/seen works are excluded.
See [product scope and actual label coverage](docs/milestone2/PRODUCT_DISCOVERY.md).

The [evidence experiment](http://127.0.0.1:8008/evidence) retains the fixed text
shortlist, source excerpts, evidence-removal controls and abstention. Its bounded
210-work bank and four explicit research criteria are distinct from the full
automatic catalogue. [Hierarchical-facet prior art](docs/milestone2/HIERARCHICAL_FACETS_RESEARCH.md)
documents direct film/novel precedents and a proposed next experiment.

Terminology: LightGBM is a tabular model. A separate **562,464-parameter causal
language model** was trained from random weights on local summaries and teacher
features. Its measured source interpretation remains weak; the default demo uses
cached DeepSeek evidence. See [the final handoff](docs/milestone2/FINAL_HANDOFF.md)
and [one-person reading pilot](docs/milestone2/transfer/HUMAN_READING_PILOT.md).
Validated cross-domain preference gains remain open work.
The older bootstrap evaluation has known leakage/label limitations documented in
the recovery guide. It should not be presented as a production accuracy benchmark.

## Get the datasets

The original CSVs and trained artifacts are excluded from Git. The three source
datasets are now downloaded locally; see [the recovery audit](docs/milestone2/DATA_RECOVERY.md).
The upstream dataset
retrieval script (added in commit `6fcda21`, merged as `00a02c4`) restores the sources:

```bash
.venv-research/bin/python -m pip install kagglehub==1.0.2
.venv-research/bin/python scripts/fetch_public_datasets.py
```

The public downloader needs no login for the sources verified in this run. The
upstream `scripts/fetch_datasets.sh` remains available for users of Kaggle CLI (install `kaggle`, configure its API token, then run `./scripts/fetch_datasets.sh`).
It fills `movie_dataset/`, `music_dataset/`, and `book_dataset/` from
[The Movies Dataset](https://www.kaggle.com/datasets/rounakbanik/the-movies-dataset),
[MovieLens 20M](https://www.kaggle.com/datasets/grouplens/movielens-20m-dataset),
[Spotify](https://www.kaggle.com/datasets/vatsalmavani/spotify-dataset), and
[7k Books](https://www.kaggle.com/datasets/dylanjcastillo/7k-books-with-metadata).

## Run the MVP

```bash
python3 -m venv .venv-api
.venv-api/bin/pip install -r apps/api/requirements.txt
PYTHONPATH=apps/api .venv-api/bin/python -m recros_api.seed --reset --limit 800
PYTHONPATH=apps/api .venv-api/bin/uvicorn recros_api.main:app --reload
```

Open [http://127.0.0.1:8000](http://127.0.0.1:8000).

The app stores local state in `apps/api/data/recros.db` (ignored by git). The seeder reads the downloaded CSV datasets. Users can choose domains, genres, moods, and exploration level; recommendations are scored across domains and updated from like/save/skip feedback.

## Auth and operations

The browser uses a bearer token issued by the guest-user endpoint. API clients can use real credentials:

```bash
curl -X POST http://127.0.0.1:8000/api/auth/register \
  -H 'content-type: application/json' \
  -d '{"email":"you@example.com","password":"at-least-8-chars"}'
```

For a full retrain from all ratings:

```bash
RECROS_ML_CONFIG=ml/config.full.yaml ./scripts/retrain.sh
```

The API hot-loads a changed `ml/artifacts/bundle_latest` on the next model-backed request. A cron example is in `scripts/retrain.cron.example`.

## Container

After running the ML pipeline so `ml/artifacts` exists:

```bash
docker compose up --build
```

The container persists its SQLite database in the `recros_data` volume and serves the app at http://127.0.0.1:8000.

## Project areas

- `apps/api`: FastAPI API, SQLite schema, content-first recommender, and dataset seeder.
- `apps/web`: browser UI for onboarding and recommendations.
- `ml`: existing offline LightGBM training pipeline, kept for the next ranking iteration.
- `run_recros.sh`: one-command local runner after installing `.venv-api`.
